# 4G：流量、短信与基带信息导入

本文说明如何使用 4G 功能。**当前实机只验证到"驱动与控制通道正常、无 SIM 时
报 `sim-missing`"**（见 [`2026-10-16-validation.md`](../validation/2026-10-16-validation.md)）。
插卡后的注册、流量、短信都还没有端到端实测，下面标为"待验证"的部分不要当成已知可用。

## 一、软硬件基础

| 项 | 内容 |
|---|---|
| 模组 | MSM8916 内置 Hexagon modem（`remoteproc1` / `4080000.remoteproc`） |
| 控制通道 | QMI over QRTR/SMD（`qrtr-ns`）+ `bam-dmux` + `rpmsg_wwan_ctrl` |
| 数据接口 | `wwan0`（bam-dmux 建出），由 NetworkManager 管理 |
| 用户态 | ModemManager 1.24.0、libqmi 1.36.0、rmtfs 1.1、qrtr-tools 1.1 |
| 固件 | `/lib/firmware/mba.mbn` + `modem.b00…b25` + `modem.mdt` |
| 校准存储 | `modemst1`、`modemst2`、`fsc`、`fsg` 四个独立分区，经 `rmtfs` 访问 |

固件在镜像里（构建时从固件集拷入），**校准分区不在 rootfs 里**，它们是设备
GPT 里的独立分区（见下面第四节）。分区拆分与写回用
[`tools/dist/gpt-backup.sh`](../../tools/dist/gpt-backup.sh)，它内置了完整
OpenStick GPT 表。

## 二、流量（数据连接）

### 2.1 NM 档（max / basic / slim / micro）

`wwan0` 由 NetworkManager 与 ModemManager 共同管理（`10-openstick.conf` 里已声明
`match-device=type:wwan;type:wifi`，避免被当 unmanaged）。

**max / basic 档已内置 APN 自动配置**：镜像里装了
`mobile-broadband-provider-info`（APN 数据库），并预置了一条
`4g-auto.nmconnection`，其 `gsm.auto-config=yes`。插卡并注册后，NM 会按运营商
的 MCC/MNC 自动从数据库里取 APN、用户名和密码，**不需要手动配置**。

机制见 NetworkManager 源码 `src/core/devices/wwan/nm-modem-broadband.c` 的
`try_create_connect_properties()`：`auto-config=yes` 时它调用
`nm_service_providers_find_gsm_apn(MOBILE_BROADBAND_PROVIDER_INFO_DATABASE, ...)`。

插卡后确认：

```sh
mmcli -L
mmcli -m 0                       # state 应为 registered
nmcli dev status                 # wwan0 应 connected（自动）
ip -br addr show wwan0
ip route | grep default
```

### 若自动配置失败，先按这三步查

```sh
# 1) APN 数据库在不在（缺了 NM 会报 "APN not found"）
ls -l /usr/share/mobile-broadband-provider-info/serviceproviders.xml

# 2) NM 的连接是否生成、是否 active
nmcli -f NAME,TYPE,DEVICE,ACTIVE con show
nmcli con show 4g-auto | grep -E 'gsm.auto-config|gsm.apn'

# 3) 看 NM 日志里的真实原因
journalctl -u NetworkManager -b | grep -iE 'apn|wwan|gsm' | tail -20
```

**手工指定 APN**（物联网卡常需要，或数据库里没有你的运营商）：

```sh
nmcli con mod 4g-auto gsm.auto-config no gsm.apn cmnet
nmcli con up 4g-auto
```

或绕过 NM 直接验证链路：

```sh
mmcli -m 0 --simple-connect="apn=cmnet,ip-type=ipv4"
```

常见 APN：移动 `cmnet`、联通 `3gnet`、电信 `ctnet`。

> **slim / micro 档不装 4G 组件**，没有 APN 数据库也没有 `4g-auto` 连接。
> native 档（`*-native`）没有 NetworkManager，用 `mm-connect.sh` 手动拨号，
> 见下一节。

### 2.2 native 档（*-native）

native 档没有 NM，用仓库自带的脚本：

```sh
# /etc/default/mm-connect 里设 APN=cmnet
mm-connect.sh          # 内部执行 mmcli --simple-connect，再由 networkd 对 wwan0 跑 DHCP
```

见 [`tools/net-native/mm-connect.sh`](../../tools/net-native/mm-connect.sh) 与
`25-wwan0.network`。

## 三、短信

短信走 ModemManager 的 WMS（QMI 消息服务），**没有独立的内核开关**——它复用
已经打开的 QMI 通道。`mmcli` 已编译进 messaging 支持（`messaging-list-sms`、
`messaging-create-sms` 等）。

```sh
# 列出短信
mmcli -m 0 --messaging-list-sms

# 读某一条
mmcli -m 0 -s 0

# 发送（中文按 UTF-8 文本发）
mmcli -m 0 --messaging-create-sms="text=测试,number=+8613800000000"
mmcli -m 0 -s 1 --send

# 或直接用 qmicli 走 WMS
qmicli -d /dev/wwan0qmi0 --wms-list-messages
```

**前置条件**：SIM 已注册（`mmcli -m 0` 的 state 是 `registered`）；否则短信接口
不可用。当前没有自动收信、转发或通知服务，需要自己按上面的命令操作或写脚本。

**待验证**：收信、发信、长短信拼接、中文编码、SIM 卡存储 vs 模组存储。

## 四、从备份导入基带信息（重点，容易出错）

### 4.1 先分清三类数据

| 类别 | 具体文件/分区 | 是否每机唯一 | 在镜像里吗 |
|---|---|---|---|
| 固件 | `mba.mbn`、`modem.b00…b25`、`modem.mdt` | 否（同型号通用） | 是 |
| 基带**校准/IMEI**（EFS） | `modemst1`、`modemst2`、`fsc`、`fsg` 分区 | **是，每机唯一** | **否** |
| WiFi 校准 | `WCNSS_qcom_wlan_nv.bin` | **是，每机唯一** | 取决于谁构建的镜像 |

**绝不能把别的机器的 `modemst`/`fsg` 写到本机**：里面含 IMEI 和射频校准，
写错会导致无信号、IMEI 异常，甚至是违法改串。只能用本机自己的备份。

### 4.2 `rmtfs -r` 的关键含义（必读）

镜像里 `rmtfs.service` 的启动命令是：

```text
/usr/bin/rmtfs -r -P -s
```

对照 rmtfs 源码（`storage.c`）：

- `-P`：从 `/dev/disk/by-partlabel/` 按分区名找 `modemst1`/`modemst2`/`fsc`/`fsg`。
- `-r`：**只读**。所有写操作只落到内存 shadow buffer，**不回写分区**。
- `-s`：与 mss remoteproc 同步。

**结论：当前配置下，modem 运行期对 EFS 的写入不会持久化。** 这对"临时跑一下
流量/短信"没有影响（EFS 读是对的），但意味着**不能靠设备自己把基带信息改好**。
要修改/恢复基带数据，只能用 `edl` 在分区层写入，或去掉 `-r` 重启后再操作。

### 4.3 备份（务必在刷机/改动前做）

设备进 EDL 后，用本仓库自带工具（`edl-tools/`）按分区读回。loader 用 Miko 自带的
`generic`（公开 Firehose loader 不被这些设备接受）。

如果已经有**整片镜像**，不必逐个分区读，用 [`tools/dist/gpt-backup.sh`](../../tools/dist/gpt-backup.sh)
一条命令拆开：

```sh
# 先看内置分区表
./tools/dist/gpt-backup.sh layout

# 整片镜像 → 分区文件（若镜像自带 GPT，会先校对分区表，不一致就拒绝）
./tools/dist/gpt-backup.sh split full-emmc.img nv-backup/

# 只把基带校准写回（默认只写 safe：boot/rootfs/modemst1/2/fsc/fsg）
./tools/dist/gpt-backup.sh write nv-backup/ --only modemst1,modemst2,fsc,fsg --yes
```

下面逐个分区的命令是等价的手工做法，适合只想读单个分区时用：

```sh
V=/opt/helloworld/openstick/edl-tools/venv/bin/python
E=/opt/helloworld/openstick/edl-tools/edl/edl.py
L=/opt/helloworld/openstick/edl-tools/Miko/loader-audit/generic

# 先确认分区表与名字
$V $E printgpt --loader=$L

# 逐一分区读回（modemst1/2 各 2MB，fsg 2MB，fsc 1KB）
mkdir -p nv-backup
for p in modemst1 modemst2 fsg fsc; do
  $V $E r $p nv-backup/$p.img --loader=$L
done
```

注意：

- edl 不带子命令会**卡住等设备**，必须设备已在 EDL 模式。
- `fsc` 只有 1KB（0x400），读回文件可能按扇区对齐，属正常。
- 备份文件**放在设备外**，不要放设备 rootfs 里（刷 rootfs 会丢）。
- 当前 `recovery/` 里**只有 GPT 表与 boot/rootfs 读回，没有 `modemst`/`fsg` 备份**——
  第一次做这件事前，先按上面命令补齐。

### 4.4 恢复

```sh
# 设备进 EDL 后，逐个写回（顺序不敏感，但建议 fsc/fsg 先于 modemst）
for p in fsc fsg modemst1 modemst2; do
  $V $E w $p nv-backup/$p.img --loader=$L
done
```

写完冷启动一次，让 modem 重新读 EFS。

### 4.5 WiFi 校准

`WCNSS_qcom_wlan_nv.bin` 也是每机唯一。若换用别人构建的 rootfs 导致 WiFi 变差
（关联失败、功率异常），用 [`tools/dist/dump-nv.sh`](../../tools/dist/dump-nv.sh)
在本机 dump 备份，再拷回 `/lib/firmware/wlan/prima/`。

## 五、已知坑

1. **rmtfs 启动时序**：`/dev/qcom_rmtfs_mem1` 出现前启动会
   `failed to open /dev/qcom_rmtfs_mem1` → `falling back to /dev/mem` → `SIGBUS` 崩溃。
   现在用 udev 规则 + `ExecStartPre` 等待修复（见 `build-rootfs.sh`）。
2. **mpss 首次启动可能 fatal**：历史日志见过
   `fs_rmts_pm.c:853: fatal error` 后自动 recover 再次 up。EFS/rmtfs 时序敏感，
   若反复 fatal，优先检查 rmtfs 是否在主进程起来前就绪。
3. **SIM 控制脚**（UFI103s）：`sim:sel`(GPIO2，默认 on)、`sim:en`(GPIO1)、
   `sim:sel2`(GPIO0)、`sim:en2`(GPIO3)，通过 LED sysfs 控制。若插卡无反应，
   先确认 `sim:en` 与 `sim:sel` 的状态是否与实际卡槽匹配。
4. **ModemManager 报 `at least a QMI port is required`** 是正常的——它扫到的是
   WCNSS 的 smd 节点，不是 modem；真正的 modem 是 `remoteproc1`。
