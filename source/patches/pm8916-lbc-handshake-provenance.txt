PM8916 LBC 充电握手补全 —— 依据与验证边界
==========================================

补丁：0006-power-supply-pm8916-lbc-complete-charger-handshake.patch
改动：drivers/power/supply/pm8916_lbc.c，+35 行，无删除

问题
----
电池机型（THWC MF32 / MF601SL）在**不装电池、仅 USB 供电**时，群友反馈
半小时内必重启；装电池后可稳定运行一个月。

根因（依据 PM8916 手册原文）
----------------------------
1) LBC_CHGR_CHG_CTRL (0x1049) bit7 CHG_EN 的寄存器描述：

      1 = Enables FSM controlled charging
      BOOT_DONE in the LBC_MISC peripheral must also be set to 1 in order
      that FSM controlled charging starts

   pm8916_lbc.c 从不写 LBC_MISC_BOOT_DONE (0x1642) bit7。全文件
   `grep -c BOOT_DONE` = 0，全树也无第二处。结果是驱动写了 CHG_EN=1，
   但 FSM 充电状态机并未真正启动。

2) LBC_USB_ENUM_TIMER (0x134F) 的说明：

      If USB wall charger (DCP) is detected or USB enumeration (SDP) is
      successful, SW (PBL or SBL) has to write to the ENUM_TIMER_STOP bit
      and set IBAT_MAX.  When this timer expires, FSM assumes that USB
      enumeration has failed or >100mA current has not been granted.
      It sets the ENUM_TIMER_EXP flag and sets IBAT_MAX = 90mA.

   默认 ENUM_TIMER = 0x03 = 120 秒。pm8916_lbc.c 同样从不写
   LBC_USB_ENUM_TIMER_STOP (0x134E) bit0。插 USB 两分钟后充电能力被
   PMIC 自己压到 90mA。

3) PM8916 手册自己把这两个原因列为掉电触发条件：
   PON_POFF_REASON2 (0x080D) bit3 CHARGER 的描述是
   "Triggered by Charger (ENUM_TIMER, BOOT_DONE)"。

对照同族 PM8941 的 qcom_smbb.c，这两步它都做了：
  - 第 718 行：{ SMBB_MISC_BOOT_DONE, BOOT_DONE, BOOT_DONE }
    注释 "The bootloader is supposed to set this... make sure anyway."
  - 第 742 / 750 行：{ SMBB_USB_ENUM_TIMER_STOP, ENUM_TIMER_STOP, ... }
    写了两次，第二次注释 "Stop USB enumeration timer, again"

PM8916 驱动漏了这两步。

为什么"装电池就稳"
------------------
装电池时 POWER_PATH 走 POWERED_FROM_BATTERY，90mA 的输入限制只影响充电
速度，不影响系统供电。不装电池时 POWER_PATH 走 POWERED_FROM_USB_CHARGER，
LBC 稳压到 VDD_MAX（手册 0x1040 原文："It's also the voltage that the lbc
regulates to when the battery is gone"），但 90mA 的输入预算撑不住系统峰值
功耗，母线跌到 UVLO（默认下降阈值 2.550V）后 PMIC 直接断电，无中断无日志。

改动内容
--------
在 pm8916_lbc_charger_configure() 里，写 CHG_CTRL 之前补两处
regmap_update_bits：

  1. LBC_MISC_BOOT_DONE bit7 = 1
  2. LBC_USB_ENUM_TIMER_STOP bit0 = 1

顺序：先 BOOT_DONE，再停 ENUM_TIMER，最后才写 CHG_EN|PSTG_EN。
与 qcom_smbb.c 的 smbb_charger_setup[] 顺序一致（BOOT_DONE 在最前，
ENUM_TIMER_STOP 在 CHG_CTRL 之前）。

验证状态
--------
- 编译：`make M=drivers/power/supply pm8916_lbc.ko` 通过，无 warning。
- 运行时：**未验证**。改动依据是手册原文 + 同族驱动对照，没有实机数据。

实机验证步骤（设备接入后按序做）
--------------------------------
1. 装电池、插 USB，读 LBC_USB_PWR_PTH_STS (0x1308) bit1:0，
   确认实际是 POWERED_FROM_USB_CHARGER(0x2) 还是 POWERED_FROM_BATTERY(0x1)
2. 读 LBC_MISC_BOOT_DONE (0x1642)，确认补丁写入后 bit7 = 1
3. 读 LBC_USB_ENUM_TIMER_STOP (0x134E) bit0 = 1，
   以及 LBC_USB_USB_CHG_PTH_STS (0x1309) bit5 ENUM_TIMER_EXP = 0
4. 不装电池、纯 USB 供电，每 10 秒采样
   /sys/class/power_supply/pm8916-bms-vm/voltage_now，
   观察是否还会在 120 秒后开始下跌
5. 重启后 `wdctl` 读 BOOTSTATUS，确认 POWERUNDER 是否消失

风险
----
两处都是 read-modify-write 单个 bit，且都是"置 1"，与 PM8941 同族驱动的
做法一致。风险主要在：若某批设备的 bootloader 已经写过 BOOT_DONE，本补丁
只是重复写同一个值，无副作用。ENUM_TIMER_STOP 若已置位同理。

但如果 PM8916 的 ENUM_TIMER_STOP 在硬件上语义与 PM8941 不同（手册只写了
"SW has to set this STOP bit"），可能需要调整。实机验证前不要宣称"已修复"。

回退
----
补丁是纯增量（+35 行，0 删除），反向套用即可回到原状。
